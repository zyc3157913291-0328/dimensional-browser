# 词条页面槽位规范（Page Schema）

> 状态：v1，2026-05-26
> 触发原因：用户报告「不同量纲的页面内容实际并不统一（如有些量纲的常见写法下方
> 有描述，有些没有）」。查下来不是样式问题，是**没有页面规范**——每个槽位
> 都是"有数据就渲染、没数据就整段消失"，于是页面的**结构**随数据完整度漂移，
> 读者无法形成稳定的阅读预期。

## 1. 原则

1. **结构恒定，内容可变**。每个词条页面渲染相同的槽位、相同的顺序、
   相同的标题文案。数据缺失只影响槽位**内部**，不影响槽位存在与否。
2. **空槽位必须显式可见**。留空位而不是整段消失——用户明确要求
   「找不到依旧留空占位 or 补录」。整段消失会让人误以为这个量本就没有该类关系。
3. **空槽位分三类，文案不同**（这是本规范的核心区分）：

   | 类别 | 含义 | 呈现 |
   |---|---|---|
   | 有内容 | 数据齐备 | 正常渲染条目 |
   | **不适用** | 该槽位对本条目本就不该有内容 | 说明**为什么**不适用（灰底说明句） |
   | **缺失** | 应该有、但这个工具还没收录 | 「暂缺」+ **补录**入口 |

4. **补录是唯一的填充路径**。任何"缺失"类空槽位都带补录按钮，提交后进入
   待核实队列，与「算法枚举」旁已有的补录流程共用同一套存储与状态机。

## 2. 槽位清单（顺序即渲染顺序）

| # | 槽位 | 标题 | 数据来源 | 空槽位类别 |
|---|---|---|---|---|
| 0 | 标题行 | — | `zh` / `symbol` / `category` / `structure` | 缺失（`symbol` 自检强制） |
| 1 | 领域 | — | `domain` / `domain_zh` | 缺失（自检强制） |
| 2 | 量纲 | — | 引擎算出的 `Dim` | 不适用（必然有值） |
| 3 | 常见写法 | `常见写法` | `unit_forms` + 每条的中文读音（引擎渲染） | 缺失 |
| 4 | 说明 | — | `note` | 缺失（自检已强制覆盖） |
| 5 | 同量纲异构 | `同量纲异构` | `quantities_with_dim(dim)` 去掉自己 | **不适用**：「该量纲下没有其他物理量」 |
| 6 | 定义式 | `定义式` | `formulas.json` 中 `defines == qid` | 见 §3 |
| 7 | 等价写法 | `等价写法` | `decompositions` + 同量纲单位 + 公式库 equivalence 关系 | 缺失 |
| 8 | 由物理式子生成 | `由物理式子生成` | `relations_for_dim` 正向 + 反读对偶 | **不适用**：「没有任何已知过程通过求导/积分/矩阵运算得到这个量纲」 |
| 9 | 用户补录（已核实） | — | `submissions` 中 `verified` | 不适用（无则不显示，因为是增量内容） |
| 10 | 用户补录（存疑） | — | `submissions` 中 `disputed` | 不适用 |
| 11 | 算法枚举 | `算法枚举` | 有界搜索（按需触发） | 缺失（按需触发的按钮） |
| 12 | 相关物理式子 | `相关物理式子` | `formulas_touching_dim` | 缺失（自检已强制覆盖） |

**标题文案固定**。同一槽位在不同词条页面上必须用同一句话，不允许出现
「等价写法」与「其他写法」两种叫法。

## 3. 定义式的三态

定义式是本规范里唯一有**两种"空"**的槽位，必须区分：

| 状态 | 判据 | 呈现 |
|---|---|---|
| 有定义式 | 存在 `defines == qid` 的公式 | 列出公式 + 一句「它在说什么」 |
| **本来就没有** | `quantity.defined_as ∈ {"si-base", "umbrella"}` | 显示 `definition_note`，说明为什么没有 |
| **尚未收录** | 两者都不满足 | 「暂缺」+ 补录入口（kind=`definition`） |

- `si-base`：SI 基本量，由基本单位（固定常数）确立。长度的定义是米，
  不是某个公式——给它编一条定义式是错的。
- `umbrella`：总称量纲（如「能量」）。动能、势能、功、力矩、热量都落在
  M·L²·T⁻² 上，没有统一公式。**这正是「量纲相同 ≠ 物理量相同」的最好教材**，
  所以不是缺陷而是需要讲清楚的特性。

「缺失」与「不适用」混为一谈是数据建模错误：前者要人去补，后者补了反而是错的。

## 4. 「由物理式子生成」为什么要反读

数据里 `derivative` 关系 9 条、`integral` 只有 3 条，看起来严重不对称。
但求导与积分互为逆运算，**每条 derivative 都同时断言了一条 integral**：

```
F = -dU/dx   ⟹   U = -∫F dx       （微积分基本定理，量纲关系完全一样）
```

所以建树时对每条 `derivative` / `integral` 关系**双向读一遍**：原方向发一条边，
掉头方向再发一条（`kind` 互换，源改成 `rel.to`）。判据严格——只有当
`apply(源量纲, 掉头运算) == 目标量纲` 时才发，不猜不外推。

反读出来的边带 `source.inverse = true`，界面明确标注「由 X 反读得到」，
不假装另有一条公式。用户报告「没有由积分生成的量纲」正是建模漏了这一维。

## 5. 补录的种类

`submissions.json` 的条目带 `kind` 字段，决定核实通过后挂到哪个槽位：

| kind | 填什么槽位 | 用户要提供 |
|---|---|---|
| `formula` | 该量纲的等价写法 / 生成关系 | 表达式 + 说明或出处 |
| `definition` | 定义式 | 定义式 + 说明或出处 |
| `unit_form` | 常见写法 | 惯用单位写法 + 说明或出处 |
| `note` | 说明 | 一句话描述 |

「存疑」的提交一律只展示、不填槽位，保留用户原文（既有约定不变）。

## 6. 一致性由自检与审计保证

- `audit_pages.py`：逐条列出每个槽位的缺失条目。**上线前必须跑一遍**，
  任何新增的"缺失"都应该是已知且有补录入口的。
- `registry.selfcheck()` 把结构必需项（`symbol`/`category`/`domain`/
  `unit_forms`/`decompositions`/`note`）当硬约束。
- 关系类槽位（同量纲异构、生成关系）的空缺是正常的，不算自检错误。
