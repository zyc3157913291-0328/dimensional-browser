# 量纲关系浏览器

输入一个单位或物理量的名称（牛、力矩、电场强度、转动惯量……），
看它的 SI 量纲、同量纲的各种写法，以及**产生这些关系的现实物理式子**。
每一步都保留中文名。

设计文档见 [`docs/2026-05-26-dimensional-relation-browser-design.md`](docs/2026-05-26-dimensional-relation-browser-design.md)。

## 运行

```powershell
cd $env:DSH_PROJECTS\dimensional-browser
$env:DSH_ANACONDA\python.exe server.py
```

> `DSH_*` 由工作区 `tools/machine-paths.ps1` 定义到**用户级环境变量**。
> ⚠️ **已启动的 DSH 会话里它们可能还是空的** —— 子进程继承的是父进程的环境块，
> 而 DSH 主进程在变量写入之前就启动了。遇到这种情况**重启一次 DSH**，
> 或本轮直接用本机实际路径：
> `cd I:\AI\DSH\workspace\projects\dimensional-browser` + `I:\Anaconda\python.exe`。

自动打开 <http://127.0.0.1:8765/>。常用参数：


## 它展示什么

以「电场强度」为例：

```
电场强度 (E_field)  [vector]  电磁学

  M·L·T⁻³·I⁻¹     质量·长度·时间⁻³·电流⁻¹
  单位电荷所受的电场力，E = F/q。N/C 与 V/m 量纲相同，后者在静电学里更常用
  —— 两种写法能互相换算，正是量纲分析给出的结论。

  ── 常见写法（单位写法 + 中文读法）─────────────────
  N/C                牛每库仑
  V/m                伏每米
  kg·m/(s^3·A)       千克·米每秒的三次方安培

  ── 同量纲异构 ────────────────────────────────
  该量纲下没有登记其他物理量……

  ── 定义式 ───────────────────────────────────
  E = F/q
  电场强度等于单位电荷所受的力。这是「电场强度」的定义式（比值型）。

  ── 等价写法 ─────────────────────────────────
  ≡ kg·m/(s^3·A)     千克·米每秒的三次方安培
  ≡ N/C              牛每库仑
  ≡ V/m              伏每米
  ≡ J/(C·m)          焦每库仑米

  ── 由物理式子生成 ────────────────────────────
  ∂ V                伏          ← E = -dU/dx
     电势对长度求导得电场强度：这就是 V/m 这个单位的物理来源

  ── [展开更多] 算法枚举 ────────────────────────
  ? A·m·T            安·米·特斯拉  〔算法枚举〕
     下面这些组合由算法枚举得到，量纲上完全正确，
     但尚未找到使用它们的现实物理式子。

  ── 相关物理式子 ──────────────────────────────
  E = F/q            电场强度等于单位电荷所受的力     〔比值型〕
  E = -dU/dx         电场强度等于电势的负梯度         〔梯度型〕
```

每个页面的槽位是**固定的 6 个、顺序固定**——没有内容的槽位也会显示，
并说明是「不适用」还是「暂缺」（暂缺带补录入口）。

以「力矩」为例，会同时列出**力矩 / 弯矩 / 能量 / 功 / 各种势能**多张卡片——
它们量纲完全相同（`M·L²·T⁻²`），界面上以「同量纲异构」显式标注。
这是本工具最有教学价值的一处：量纲相同不足以判定物理量相同。

## 边的类型

树上的每条边都标明来源类型，因为它们是**不同性质的话**：

| 标记 | 类型 | 含义 |
|---|---|---|
| ≡ | 等价重写 | 同一个量的另一种写法，量纲不变（`N` = `kg·m/s²`） |
| ∂ | 求导生成 | 某量求导后量纲降低，恰好是这个量（`J` → `F = -dU/dx`） |
| ∫ | 积分生成 | 某量积分后量纲增加，恰好是这个量（`N` → `p = ∫F dt`） |
| ▦ | 矩阵运算 | 矩阵/张量运算后的元素量纲（`I = ∫∫∫ r²ρ dV`） |
| ? | 算法枚举 | 有界搜索所得，**尚未找到使用它的现实物理式子**（暖色区块 + 虚线） |

前三类都标注了来源公式。算法枚举类**不来自任何公式**，界面上单独成区块，
明确告知「量纲正确但无物理来源」。

## 搜索：边打边出候选

输入框不是「敲完再点查询」的——**每敲一个字就在下面列出可能的结果**，
按匹配强度排序，每行标注命中理由：

```
输入  dcqd        → 电场强度（完全相同）   ← 拼音首字母
输入  dianchang   → 电场强度（名称开头）   ← 拼音全拼
输入  kgm         → 千克（输入更长，包含该名称）  ← 反向包含
输入  电场强渡     → 电场强度（字符部分重合，可能是错字）
```

匹配梯度（`engine/matcher.py`，从强到弱）：

| 类型 | 例子 |
|---|---|
| 完全相同 | `牛` → 牛 |
| 名称开头 | `电场` → 电场强度 |
| 名称包含 | `矩` → 力矩、弯矩 |
| **反向包含**（输入比候选长） | `kgm` → 千克、质量；`ohmxyz` → 欧 |
| 拼音全拼 | `dianchang` → 电场强度 |
| 拼音首字母 | `dcqd` → 电场强度 |
| 子序列 | `dqd` → 电场强度 |
| 错字兜底 | `电场强渡` → 电场强度 |

几条刻意的取舍：

- **不做全文检索**。候选只有 84 个（57 物理量 + 27 单位），摊平成 700 多个
  字段逐条打分只要 **1 ms**，比建索引便宜得多。打分逻辑全在 Python 里，
  「为什么这条排在前面」永远可以在测试中复现。
- **反向包含要求候选至少 2 个字符**。否则输入里含哪个字母就命中哪个符号，
  `abc` 会带出 `a`、`c`、`A`、`C`、`B` 一串噪声。
- **弱字段只认强匹配**。分类与领域字段权重低，且只接受「相同/开头/包含」——
  否则输入「电」会因为分类命中而把整个电磁学分类翻出来。
- **同一量纲最多 3 条**。同量纲异构是教学重点，但不该霸屏。
- 键盘 `↑` `↓` 移动、`回车` 采用高亮项、`Esc` 关闭；`Ctrl/Cmd+K` 聚焦。

### 拼音表是构建期生成的

运行时仍然**零第三方依赖**。拼音来自 `pypinyin`，但只在**构建期**用它把
数据里出现过的 629 个汉字读成 `data/pinyin.json`（全拼 + 首字母），
运行时只查表。

```powershell
python gen_pinyin_table.py     # 新增中文条目后重跑
python selfcheck.py            # 会核对是否有汉字漏进表里
```

代价是新增中文条目时表不会自动更新，所以 `selfcheck.py` 每次都核对一遍——
漏字的后果只是那个字不能用拼音搜到，不影响任何正确性，所以它算提示而非阻塞。

## 搜索历史

**在搜索框里**，不在页面上常驻。聚焦空输入框时从搜索框下方弹出，
离开搜索框就收起：

- 按时间倒序（越近越靠前），条尾显示时间，点即重查
- 每行右侧 `×` 删单条，面板标题右侧「清空全部」
- 输入文字后面板切换为候选，标题右侧留了「看历史（N 条）」的切换入口
- 存储：浏览器 `localStorage`（key `dimbrowser.history.v1`），不上传
- 上限 **50 条**，去重（同一条查询只保留最新一次并提到最前）
- 纯前端功能，后端无任何改动；隐私模式下自动降级为无历史

另：搜索历史显示的标签是**你点击时的文本**——点「重力」跳到 `weight` 页面，
历史里显示的是「重力」而不是 `weight`。

## 前进 / 后退

每次查询（含点击词条跳转）都 `pushState` 一条历史，浏览器前进后退可用，
刷新与收藏走 URL hash（`#q=牛`）。退到头会回到首页分类浏览。

两个容易踩的点写在代码注释里：

- 早期用 `replaceState` 写 hash，后退键永远退不回去
- 不能同时监听 `hashchange`——`pushState` 改 hash 不触发它，
  但浏览器后退会同时触发 `popstate` 与 `hashchange`，一次后退渲染两遍

## 公式补录（四个槽位共用一条通道）

页面上的槽位找不到内容时会留出空位并给「补录」按钮，
**四种补录各填各的槽位**：

| 种类 | 填哪个槽位 | 必填 |
|---|---|---|
| `formula` 公式来源 | 等价写法 / 由物理式子生成 | 表达式 +（说明或出处） |
| `definition` 定义式 | 定义式 | 定义式 + 目标物理量 +（说明或出处） |
| `unit_form` 常见写法 | 常见写法 | 单位写法 + 目标物理量 +（说明或出处） |
| `note` 条目说明 | 说明 | 描述 + 目标物理量 +（说明或出处） |

弹窗按种类切换标题、必填项与提示语，但字段是同一批。

**状态机**：`pending`（待核实）→ `verified`（转正）/ `disputed`（存疑）。

- **只有 `verified` 填槽位**，作为「用户补录（已核实）」区块展示
- `pending` / `disputed` 只展示、不填槽位——它们尚未被确认为真实内容
- **存疑不删除**：`disputed` 只加黄色标记，你填的原文原样保留
- 说明类补录**只能填空白**，不覆盖数据里已有的描述

右下角的角标显示当前提交总数，点击可看完整清单。

**数据归属**：所有提交写在 `dimensional-browser/submissions.json`，与 `data/`
目录完全分开。工具永远不会覆盖或改写你填的内容，只更新状态字段。

**关于核实**：本轮只做了提交与存储，**尚未接入自动核实**。原因是本地服务器
进程没有联网能力——`web_search` 属于 agent 会话的工具。所以 `verify` 字段
结构已预留（来源链接、判断依据、核实时间），`promote()` / `dispute()` 两个
方法也实现并测试了（含非法状态转换的拦截），接核实流程时只需填状态。

### 公式符号表（折叠）

「相关物理式子」区块里，每条公式下有一个折叠开关「▸ 展开符号说明（N 个字母）」，
展开后是一个四列表格：

```
符号    名称      单位          物理意义
F       力        N　kg·m/s²    物体之间的相互作用，能使物体形变或改变运动状态
m       质量      kg            质量（力学）
a       加速度    m/s^2         加速度（几何与运动学）
```

- 符号名与名称都是**可点击的**，点了跳到该量纲的页面。84 组 `(符号, 量纲)`
  里 79 组可跳转，余下 5 组（`Phi` 磁通量、`k_e` 静电力常量、`theta` 角位移、
  `epsilon` 应变、`Omega` 立体角）对应的量没登记在物理量表里，跳过去也是空页
- 解析走两跳：先查 `data/symbol_glossary.json` 的例外表（58 条），
  再用 `(符号, 量纲)` 在物理量表里匹配。实测 84 组里有 26 组能被第二跳
  自动解决，所以例外表只需写剩下的——且大多只要补一个更精确的中文名
  （`E_k` 应为「动能」而不是泛泛的「能量」）
- **按公式存，不全局存**：`U` 既是势能又是电势，`L` 既是角动量又是电感，
  `p` 既是动量又是压强。全局表必然张冠李戴，而「这句话里 m 是质量」本身
  就是最有价值的信息
- 自检会检查**同一签名里一个符号只能有一个量纲**。这条规则是补出来的：
  `magnetic_force_lorentz` 的 tex 写的是 `F = q·v·B`，`lhs.symbol` 却写成了
  `B`，只比量纲的齐次性检查完全放行，但符号表里因此多出一行
  「B = 磁场力」且没有跳转链接——**看起来完全正常**

### 定义式（单独列出，三种状态）

「定义式」区块回答「这个量怎么被定义出来的」。规范见
[`docs/2026-05-26-page-schema.md`](docs/2026-05-26-page-schema.md)。

判据是公式数据里的 `defines` 字段（指向被定义的物理量 id），不是量纲推断。
原因：曾试过「新量是否引入新基本量纲」的启发式，结果把 `F = m·a`
（牛顿第二定律）和 `F = G·m₁m₂/r²`（万有引力定律）都判成了定义式——
**定律与定义式的区别是物理知识，不是量纲能算出来的**，必须显式标注。

**49 个物理量有定义式**（57 个条目里），例如 `F = m·a`、`E_k = ½mv²`、
`R = U/i`、`c = Q/(m·ΔT)`、`f = 1/T`、`sigma = F/A`、`E_mod = sigma/epsilon`。

剩下 8 个**本来就没有定义式**（6 个 SI 基本量 + 2 个总称量纲），
工具把「不适用」与「缺失」严格分开：

| 状态 | 判据 | 呈现 |
|---|---|---|
| 有定义式 | 存在 `defines == qid` 的公式 | 列出公式 + 一句「它在说什么」 |
| **本来就没有** | `defined_as = si-base`（长度/质量/时间/发光强度/热力学温度/物质的量）或 `umbrella`（能量、化学势能） | 说明**为什么**没有 |
| **尚未收录** | 两者都不满足 | 「暂缺」+ 补录入口 |

把「缺失」和「不适用」混为一谈是数据建模错误：前者要人去补，后者补了反而是错的——
给「长度」编一条定义式，写的必然是错的。

「能量」是 `umbrella` 而不是缺失：动能、势能、功、力矩、弯矩、热量、化学势能
全都落在 `M·L²·T⁻²` 上，它**没有**统一的定义式，而这正是「量纲相同 ≠
物理量相同」的最好教材。

## 页面槽位规范：结构恒定，内容可变

用户报告「不同量纲的页面内容实际并不统一（如有些量纲的常见写法下方有描述，
有些没有）」。查下来不是样式问题，是**没有页面规范**——原先每个槽位都是
「有数据就渲染、没数据整段消失」，页面**结构**随数据完整度漂移，
读者无法形成稳定的阅读预期。

现在每个词条页面渲染**相同的 6 个槽位、相同的顺序、相同的标题文案**，
数据缺失只影响槽位内部，不影响槽位存在与否：

| 顺序 | 槽位 | 空槽位类别 |
|---|---|---|
| 1 | 常见写法（写法 + 中文读法 + 补充说明） | 缺失 → 补录 |
| 2 | 同量纲异构 | **不适用**：该量纲下没有别的物理量 |
| 3 | 定义式 | 见上节三态 |
| 4 | 等价写法 | 缺失 → 补录 |
| 5 | 由物理式子生成（求导/积分/矩阵） | **不适用**：没有已知过程产生它 |
| 6 | 相关物理式子 | 缺失 → 补录 |

再加上标题区的符号/类别/领域/结构/量纲/说明。**空槽位必须显式可见**——
整段消失会让人误以为这个量本就没有该类关系。

「常见写法」是这次的重点改动：原先只有裸字符串列表，描述只能靠数据里的
`note` 字段，于是结构随数据漂移。现在**中文读法由引擎生成**——
`kg·m/s^2` 读作「千克·米每二次方秒」，这类读法完全可以由求值器沿 AST
拼出来，所以它对每一条都存在，剩下的只是可选的补充说明。

覆盖情况用 `audit_pages.py` 逐条审计：

```powershell
python audit_pages.py
```

## 求导与积分成对出现

用户报告「没有由积分生成的量纲，按理该与求导成对出现」。查下来**不是数据
缺失，是建模漏了一维**：数据里 `derivative` 关系 9 条而 `integral` 只有 3 条，
看起来严重不对称；但求导与积分互为逆运算，**每条 derivative 都同时断言了
一条 integral**：

```
F = -dU/dx   ⟹   U = -∫F dx      （微积分基本定理，量纲关系完全一样）
```

所以建树时对每条 `derivative` / `integral` 关系**双向读一遍**：原方向发一条边，
掉头方向再发一条（`kind` 互换，源改成 `rel.to`）。判据严格——只有当
`apply(源量纲, 掉头运算) == 目标量纲` 时才发，不猜不外推。

反读出来的边带 `source.inverse = true`，界面明确标注「反读」并写出原方向，
不假装另有一条公式。若数据里已经显式声明了同一条边（例如冲量定理已经写了
`p = ∫F dt`），显式那条优先——去重键是**边语义**（kind + 源表达式 + 变量 +
阶数），不含公式 id，所以两处描述同一件事时自动合并。

效果：能量页面上出现了「`N` 对 `x` 积分」，速度页面上出现了「加速度对 `s` 积分」，
电势、电荷量、角动量页面也各自有了积分来源。

## 算法枚举的去重按「结构规范形」

用户报告「算法枚举时会重复枚举，如 `N·m` 和 `m·N`」。根因是去重键用的是
`parse → render`，它只归一**语法**、不归一**交换律**，于是同一个组合在
「常见写法」和「算法枚举」里各显示一遍。

现在去重键走 `parser.canonical_expr()`，它做三件事：

1. 把除法与负幂统一成**指数**（`N/m^2` 与 `N·m^-2` 同键）
2. 乘法因子按基名排序，同名基的指数相加（`m·m` → `m^2`）
3. 数字系数单独提出，不参与因子排序

它是**比较键**不是展示文本——界面上仍走单位渲染器（`kg·m²/s²`）。
同一个键也用在补录匹配上，所以用户提交 `m·N` 能匹配到库里已有的 `N·m`。

### 搜索候选（歧义输入不猜）

物理符号天然有歧义：`I` 在文献里同时是电流、冲量、转动惯量，`p` 是动量，
`U` 是势能也是电势。**硬绑到某一个条目上是猜，猜错比不猜更糟**，所以：

- 精确命中的同时，也把**其他候选**一并列出（输「势」命中「势能」，
  同时给出电势能/化学势能/重力势能）
- 候选卡片显示：中文名 · 符号 · 量纲 · 常见单位 · 一句话说明，点击直达
- 实时联想面板按匹配强度排序，每行标注命中理由（见上文「搜索」一节）

## 测试

```powershell
python test_engine.py        # 496 项断言，66 个测试函数
```

覆盖重点按「哪里的错误最隐蔽」排序：代数规则 > 数据自检 > 有界搜索 >
建树 > 解析器 > 求值器。其中几条是专门锁住实现期踩过的坑：

- `det` 的量纲是 `D^n` 而非不变（2×2 平移矩阵的 det 是面积 `[L²]`）
- 求导与积分互逆；**分母的幂次必须生效**（`E_v = I_v/r²` 曾少减一阶长度）
- `var_dim('s')` 必须是时间而非长度（单字母歧义）
- `P = dW/dt` **不应**出现在「力」的分支下（串味回归）
- 搜索结果必须以 `kind=search` 标注且不来自公式
- 默认查询**不得**跑搜索（有成本，且不属于主体内容）
- 有界搜索的最慢单次 ≤ 2s（验证「有界」这个承诺）
- **规范形去重**：`N·m` 与 `m·N` 必须同键，且枚举结果里不得出现已有写法的等价形式
- **求导/积分成对**：每条 derivative 关系的源量纲页面上必须有积分边
- **页面槽位不变量**：无定义式的条目必须由 `defined_as` 解释清楚，不允许留说不清的空白
- **同一签名里一个符号只能有一个量纲**（这条规则抓出了 `F = q·v·B` 写成
  `lhs.symbol = B` 的真实数据错误）
- **常见写法逐条有中文读法**（这正是「有些有描述有些没有」的修法）
- **补录四种种类各填各的槽位**，pending 一律不填槽，说明类不覆盖已有描述

### 修过的隐蔽 bug（都写进了测试）

1. **符号表串台**：DOM id 用 `glo-{公式id}`，而同一公式会出现在多张卡片下，
   产生重复 id，`getElementById` 永远返回第一个——点「重力」的展开，
   展开的却是「力」的。改成在**自己的父容器**里查找，不依赖全局 id。
2. **历史丢失标签**：`histLoad()` 的 `.map()` 只重建 `{q, ts}`，
   **把 `label` 字段丢掉了**，导致「历史显示点击文本」的功能从未生效——
   存储里是对的，读出来的对象却没有 label，渲染层只能退回显示查询词
   （点「重力」跳转，历史里显示英文 id `weight`）。
3. **只有候选没有实体时被当成查不到**：`search()` 里 `if (!entities.length)`
   的早退，让输入「势」这种只出候选的情况直接报错，候选面板从未渲染。
4. **反读对偶的前置比较写反了**：掉头后的边「源 = `rel.to`、结果 =
   `rel.from_`」，曾写成 `src_dim != dim` 就跳过——那是拿**源的量纲**跟
   **结果的量纲**比，结果一条对偶边都出不来。而且这个错误看起来完全合理，
   只有数一数「积分边还是 0 条」才发现。
5. **折叠按钮卡在文字中间**：button 的 DOM 位置放在了隐藏项**之前**，
   展开后必然读成「abc 收起 efg」。这是结构错误不是样式问题，
   正确顺序是「可见项 → 省略号 → 隐藏项 → 按钮」。
6. **目录上下弹跳**：`transform: translateY(-33%)` 的百分比按**自身高度**
   算，条目一拉长整条目录就跳。改用撑满视口的 flex 包裹居中。

## 「展开更多」（有界搜索）

界面上每张卡片下方有一个按钮，点击后跑有界搜索，就地把结果插进卡片。
它单独做成按需触发而非默认显示，理由有两条：搜索有成本（实测 200–300 ms），
而且设计上它是「限定之外的补充」，不该默认出现在主体内容里。

搜索的数学框架是**向量格上的最短路**：每个单位的量纲向量是格点，
一次分解就是从原点走到目标的路径。用 BFS 后天然按复杂度排序、可分批、可设边界。

剪枝参数（`engine/search.py` 的 `SearchBounds`）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `max_atoms` | 3 | 最多几个单位参与 |
| `max_power` | 3 | 单个单位的幂次上限 |
| `max_numerator_atoms` | 3 | 分子里最多几个单位 |
| `max_weight` | 10 | 代价上限。必须高于最复杂导出单位的 L1 范数，否则 `Ω` 自己都搜不到 |
| `max_results` | 18 | 返回条数上限 |
| `max_unit_cost` | 2.0 | 候选单位代价上限，正好只放行 SI 基本与导出单位 |
| `max_nodes` | 6000 | 节点预算，保证时间上界 |

**这些剪枝会漏掉某些数学上合法的分解**，所以结果一律标注为「有界搜索」，
绝不声称是全部可能。界面上也如实写明这一点。

实现上有一处关键取舍：**每个 (状态, 单位) 只产生一个位移**，而不是
对每个单位尝试所有幂次。理由是分支因子——23 个生成元 × 6 个候选幂次
= 每状态 138 条边，深度 3 就是 260 万次扩展（实测 4.7 秒）；合并成一个
位移后每状态 23 条边（降到 240 ms）。代价是同一单位在一条路径里只出现
一次，但教学上有意义的组合几乎都是「几个不同单位各出现一次」。

被排除在搜索之外的单位及理由（都写在 `search.py` 里）：

| 单位 | 理由 |
|---|---|
| `bar` `min` `h` | 单位制混搭，只产生 `s·bar`、`Pa·min` 这类噪声 |
| `g` | 带词头（1 g = 0.001 kg），与 kg 同时参与会产生 `Pa·g/kg` 这类纯比例因子组合 |
| `rad` `sr` | 无因次，不改变量纲 |

## 架构

```
dim          ← 无依赖，纯向量空间（量纲 = 基本维度幂次的整数向量）
parser       ← 无依赖，纯语法（文本 → AST）+ 结构规范形（去重键）
algebra      ← dim                       代数规则：运算如何改变量纲
evaluator    ← dim, parser               AST → (系数, 量纲, 中文写法)
registry     ← 以上全部 + 数据文件         加载、别名归一、启动自检、符号表
search       ← dim, registry             向量格有界 BFS，最短路分解
matcher      ← registry                  即时联想：把候选摊平打分（1 ms/次）
submissions  ← 无依赖（只读写自己的文件）  用户补录的存储与状态机（四种种类）
tree         ← registry, search, submissions  建树：公式库优先 → 分解表 → 搜索 → 补录
api          ← 以上全部                   JSON 端点，唯一出口
```

依赖方向单向，不允许反向：`registry` 能 import `evaluator`，
但 `evaluator` 绝不能 import `registry`——否则测 evaluator 就要先造一份完整数据。
`submissions` 刻意不依赖 registry，它只关心自己的文件与状态机，
所以测试它不必加载任何物理数据。

前端只有渲染逻辑，**不含任何量纲计算**。界面上显示的每一条关系都必然
经过引擎的齐次性校验，不可能出现「前端算出来好看但物理上错」的内容。

公式渲染用 HTML 的 `<sub>` / `<sup>` 自绘（把 `kg·m^2/s^2` 变成 `kg·m²/s²`），
而不是引入 KaTeX——为了守住零依赖原则。

## 关于弧度的一个设计变更

设计文档原定用 `RAD` 伪维度让力矩与能量在量纲上分开。**实现证明不可行**：

```
若 dim(θ) = {RAD: 1}，要使 W = M·θ 成立需 dim(M) = {RAD: -1}
但向量空间里 rad·rad = {RAD: 2}，不是 0
「弧度相乘相消」是模 2 运算（XOR），与量纲的加减代数不兼容
```

改为如实反映物理事实：`dim(力矩) == dim(能量) == M·L²·T⁻²`。
这不是缺陷，而是量纲分析的核心一课，工具改用 `homogeneous_with`
字段 + 界面警示来区分。详见设计文档 2.9。

## 已知限制

- **补录的自动核实未接入**。提交能存、能看、能标记三态，但「上网核实是否
  真实存在」这一步需要人工触发（详见「公式补录」一节）。
- **温度偏移未实现**。`°C`/`°F` 需要 `offset` 字段，当前单位表只有换算因子，
  所以只支持线性单位。热力学温度本身已收录（量纲 `Θ`），
  但与摄氏温度的零点差在量纲上看不出来——这是量纲法的边界，不是实现缺陷。
- **矩阵只标注结构，不做实际运算**。`structure: matrix` 用于展示与规则分发；
  `algebra.det` / `trace` / `matmul` 有实现与测试，但引擎不会真的构造矩阵、
  算行列式——建树流程尚未接入具体矩阵实例。
- **公式列表在每张卡片下重复**。同量纲的多张卡片（如力矩/弯矩/能量/功）
  会各自列出同一批公式。教学上有强化作用，但内容冗余。
- **搜索结果里仍有少量无意义组合**（如 `m·kg·Hz^2`）。这是算法枚举的固有
  属性，已用暖色区块 + 警示文字与公式来源区分，界面也明说它们
  「尚未找到使用它们的现实物理式子」。
- **符号表里仍有少数符号无跳转**（`dT` 温度变化、`k_e` 静电力常量、
  `theta` 无因次角位移）——因为它们对应的量没登记在物理量表里，
  跳过去也是空页。
- **联想是「名称检索」不是「语义检索」**。它能处理拼音、子序列、错字，
  但不懂同义词之外的意思：输入「黏黏的东西」不会找到动力黏度。
  真正的语义理解需要词向量或 LLM，与「零依赖、可离线打包」的目标冲突，
  所以这一层留给用户补录的别名（`aliases` 字段）去覆盖。
- **右侧目录在窄屏（≤ 1400px）隐藏**。这是为了避免挤占正文宽度做的取舍，
  窄屏形态尚未设计。
- **「由物理式子生成」为空时是不适用，不是缺失**。30 个条目没有任何已知
  过程能产生它们的量纲。这是诚实的结果，但读者可能会误以为是漏了数据，
  所以界面上写明了理由。
- **打包尚未实测**。`engine/paths.py` 已经把「只读资源」与「用户可写数据」
  分开（打包后资源取 `sys._MEIPASS`，`submissions.json` 落在当前工作目录），
  但还没有真的用 PyInstaller 打一个 exe 验证过。
- **拼音表需要手工重建**。新增中文条目后要重跑 `gen_pinyin_table.py`，
  否则新字不能用拼音搜到（`selfcheck.py` 会提示）。
